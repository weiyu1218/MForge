这是一个完全基于官方 sigstore-python 原生 API 构建的工业级独立封装方案。

在真实的服务器或集群环境中，使用 Sigstore 的核心痛点在于身份校验策略 (Policy) 和 OIDC Token 的无头 (Headless) 注入。以下代码和配置方案直接针对这些真实场景进行设计，你可以将其作为一个独立的模块（例如 security/sigstore_manager.py）直接导入并调用。

1. 环境准备
确保使用最新版的 sigstore，因为其 V3 版本的 API 引入了更标准的 Bundle 规范，摒弃了旧版分离的 .sig 和 .crt 文件。
pip install "sigstore>=3.0.0"

2. 核心独立实现：sigstore_manager.py
这个模块封装了签名与验签的完整逻辑，并且抛弃了所有 Mock 代码，直接与 Sigstore 的 Fulcio (证书颁发) 和 Rekor (透明日志) 生产环境服务通信。

import os
import json
import logging
from pathlib import Path
from typing import Optional

# Sigstore 原生 API
from sigstore.models import Bundle
from sigstore.sign import Signer
from sigstore.verify import Verifier
from sigstore.verify.policy import Identity
from sigstore.errors import Error as SigstoreError

logging.basicConfig(level=logging.INFO, format="%(asctime)s - %(levelname)s - %(message)s")
logger = logging.getLogger(__name__)

class ArtifactSigner:
    """
    用于分子数据集、模型权重或生成的配置文件的工业级 Sigstore 签名器。
    """
    
    def __init__(self):
        # 默认使用 Sigstore 生产环境 (Fulcio/Rekor)
        self.signer = Signer.production()
        self.verifier = Verifier.production()

    def sign_artifact(self, file_path: str, output_bundle_path: Optional[str] = None) -> str:
        """
        对物理文件进行签名，生成 Sigstore Bundle。
        前提：环境中必须存在有效的 OIDC Token（见后文配置说明）。
        """
        target_path = Path(file_path)
        if not target_path.exists():
            raise FileNotFoundError(f"Target artifact not found: {file_path}")

        # 默认将 bundle 生成在同级目录，后缀为 .sigstore
        bundle_path = Path(output_bundle_path) if output_bundle_path else target_path.with_suffix(".sigstore")

        logger.info(f"Starting signing process for: {target_path}")
        try:
            # 执行签名请求（与 Fulcio 和 Rekor 交互）
            with self.signer as signer_ctx:
                bundle: Bundle = signer_ctx.sign_file(target_path)
            
            # 将 Bundle 序列化落盘
            with bundle_path.open("w") as f:
                f.write(bundle.to_json())
                
            logger.info(f"Successfully signed. Bundle saved to: {bundle_path}")
            return str(bundle_path)
            
        except SigstoreError as e:
            logger.error(f"Sigstore signing failed: {e}")
            raise

    def verify_artifact(self, file_path: str, bundle_path: str, expected_identity: str, expected_issuer: str) -> bool:
        """
        验证文件的签名和防篡改透明日志。
        
        参数:
        - expected_identity: 签发该文件的身份 (例如你的机器号、服务账号邮箱、或 Github Actions 仓库 URL)
        - expected_issuer: OIDC 颁发者 (例如 https://github.com/login/oauth, https://accounts.google.com)
        """
        target_path = Path(file_path)
        b_path = Path(bundle_path)

        if not target_path.exists() or not b_path.exists():
            raise FileNotFoundError("Artifact or Bundle file is missing.")

        logger.info(f"Verifying {target_path} against policy [Identity: {expected_identity}, Issuer: {expected_issuer}]")
        
        try:
            # 反序列化 Bundle
            with b_path.open("r") as f:
                bundle = Bundle.from_json(f.read())

            # 工业级验证必须指定 Policy（确认“是谁”签的，而不仅仅是“是否被签过”）
            policy = Identity(identity=expected_identity, issuer=expected_issuer)

            with self.verifier as verifier_ctx:
                # 如果验证失败，这里会抛出 VerificationError
                verifier_ctx.verify_file(target_path, bundle, policy)
                
            logger.info("Verification PASSED. The artifact is authentic and untampered.")
            return True
            
        except SigstoreError as e:
            logger.error(f"Verification FAILED: {e}")
            return False

if __name__ == "__main__":
    # --- 独立调用测试示例 ---
    # 假设你生成了一个候选分子集
    test_file = "candidate_molecules.csv"
    with open(test_file, "w") as f:
        f.write("SMILES,Score\nCCO,0.88\n")

3. 如何在无头 (Headless) / 裸金属环境中注入 OIDC Token
在你的独立代码中，Signer.production() 会自动去寻找证明身份的 OIDC Token。如果运行在本地电脑，它会弹出一个浏览器让你通过 Google/GitHub 授权；但在部署了复杂数据库和子系统健康检查的 Linux 服务器集群中，弹出浏览器会导致程序直接卡死。

既然你提到“OIDC token 可用时”，你需要通过环境变量将由 Keycloak、Vault 或 CI/CD 平台生成的 Token 喂给这段程序。

在触发签名的 Python 进程启动前，或者在系统的入口处，通过底层注入这个 Token：
# 将你获取到的真实 OIDC JWT Token 赋给此环境变量
export SIGSTORE_ID_TOKEN="eyJhbGciOiJSUzI1NiIs..."

# 运行你的智能体或生成流程
python main_pipeline.py

sigstore-python 在底层初始化时，会优先读取 SIGSTORE_ID_TOKEN。只要这个 Token 在有效期内（通常几分钟即可，因为 Sigstore 只在签名瞬间需要它来向 Fulcio 换取短期证书），代码就能瞬间完成签名并落盘，不会有任何阻塞。

4. 接入主系统的最佳实践
当你把这个 ArtifactSigner 独立测试跑通后，接入的逻辑非常简单。在你的主控逻辑或 Agent 执行完特定阶段（例如一轮分子的生成和打分全部结束，数据落盘为 CSV/SDF 时）进行调用：

# 当分子生成和打分任务完成后
dataset_path = evaluate_and_save_molecules(generators)

# 无缝接入签名模块，对高价值产物进行供应链安全存证
signer = ArtifactSigner()
bundle_path = signer.sign_artifact(dataset_path)

# 可选：将 bundle_path 或生成的 Rekor UUID 写入底层数据库（如 PostgreSQL/Neo4j），完成溯源绑定。
