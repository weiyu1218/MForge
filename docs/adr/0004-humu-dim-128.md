# ADR-0004: HUMU 编码维度 128

**状态**：已采纳
**日期**：2025-Q1
**决策者**：MoleculeForge 架构团队

## 背景

HUMU 将分子、口袋、合成路径编码到统一的 Lorentz 双曲流形 ℍ^d 上。维度 d 的选择直接影响表达能力、计算开销和数值稳定性。

备选维度：
- 64：计算快但表达能力可能不足（化学空间维度估计 20-50）
- 128：已知的最优平衡点
- 256：表达能力强但显存占用大（batch=1024 时 ~1GB/编码器）

## 决策

**选择 d=128**（即 Lorentz 坐标 129 维，含时间分量）。

## 理由

1. **化学空间覆盖**：ChEMBL 34（>2.4M 分子）的有效化学空间维度估计为 30-80，128 提供 ~2x 余量
2. **Flow Matching 兼容**：HFM-3D 在 128 维切空间上的 ODE solver 20 步足够精度
3. **GPU 友好**：4 个编码器（mol/pocket/route/intent）batch=1024 时总计 ~8GB 显存，RTX A6000 48GB 可轻松承载
4. **文献依据**：现代化学嵌入工作（ChemBERTa-2、MolCLR）常用 128-256 维度
5. **数据库索引**：Qdrant 向量集合使用 129 维 Lorentz 坐标，与 DKI 向量检索后端一致

## 后果

- 所有编码器输出为 129 维 Lorentz 坐标（128 空间 + 1 时间分量）
- proto 定义 `HCIV.coordinates` 为 `repeated float`，dim=128
- Qdrant 向量索引维度 = 129
- 切空间操作在 128 维进行

## 验证

- `test_lorentz_manifold.py` 验证 dim=128 时的 exp/log 互逆性
- 三塔编码器输出维度检查
