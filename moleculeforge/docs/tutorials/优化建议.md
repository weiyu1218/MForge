# MoleculeForge 项目优化建议

> **审核日期**：2026-05-05
> **审核范围**：全仓（13,897 Python 文件，4,273,413 行）+ zzzzz/ 数据集
> **基准文档**：MoleculeForge_CodeArchitecture.md + MoleculeForge_CoreArchitecture_v2.md

## 0. 总览（Executive Summary）

| 维度 | 健康度 | 备注 |
|---|---|---|
| 项目骨架 | 🟢 | pyproject.toml/Makefile/CI 结构完整，uv.lock 缺失 |
| 协议层 | 🟢 | 18 个 .proto 文件全部存在，service/message 定义完整 |
| 共享内核 | 🟢 | HUMU 洛伦兹流形数学正确实现；mf-core 插件系统完整 |
| 模型实现 | 🟡 | 生成器结构完整但多数未经充分训练；hfm_3d 架构齐全 |
| 微服务 | 🟡 | 服务结构正确但缺少 main.py 入口（使用 __main__.py） |
| 智能体 | 🟡 | Orchestrator 10 节点完整；Critic 仅 8 条规则（远低于 100+） |
| 数据管线 | 🔴 | data/processing 和 data/validation 完全为空；DVC pipeline 未配置 |

**总体评分**：**52/100**

**关键结论（3 句话）**：
2. **架构骨架完整但血肉不足** — 18 个 proto、24 个服务、9 个生成器、9 个 Agent 的结构和注册都到位，但数据管线（processing/validation）、测试覆盖（16 单元测试）、Critic 规则（仅 8 条）严重短缺。
3. **当前状态为"框架完整、MVP 可跑"但距离生产级差 3-6 个月** — 最大瓶颈是测试为零、数据管线缺失、Critic 规则不足。

## 1. 严重问题（BLOCKER 🔴）

> 必须修复，否则系统不可用

### 1.1 [BLOCKER-001] E2E 测试完全缺失

**位置**：`tests/e2e/`（空目录）
**证据**：`find tests/e2e -name "test_*.py"` 返回 0
**修复建议**：
1. 至少创建 `test_kras_g12c_pilot.py`（架构第 11 节要求的 KRAS G12C E2E 测试）
2. 创建 `test_multi_target_design.py`
3. 创建 `test_audit_completeness.py`

### 1.2 [BLOCKER-002] 数据管线处理层完全为空

**位置**：`data/processing/`（0 个文件）、`data/validation/`（0 个文件）
**证据**：两个目录均无任何 Python 脚本
**影响**：分子规范化、构象生成、指纹计算、片段分解、反应模板提取等核心数据处理完全未实现；数据质量检查（schema/重复/异常值）缺失
**修复建议**：
1. `data/processing/` 添加：`molecule_canonicalization.py`、`conformer_generation.py`、`fingerprint_computation.py`、`fragment_extraction.py`、`reaction_template_extraction.py`、`pharmacophore_processing.py`、`data_normalization.py`
2. `data/validation/` 添加：`schema_check.py`、`duplicate_detection.py`、`outlier_detection.py`

### 1.3 [BLOCKER-003] DVC 数据版本控制未接入

**位置**：`data/dvc/pipelines/`（0 个 YAML 文件）
**证据**：无 DVC pipeline 配置；模型权重的版本追踪机制缺失
**影响**：无法复现实验、无法追踪数据血统（违反架构 1.6 节）
**修复建议**：
1. 创建 `humu_pretrain_data.dvc.yaml`
3. 配置 DVC remote（S3/MinIO）

### 1.4 [BLOCKER-004] Orchestrator 使用 RDKitRandomGenerator 而非真实生成器

**位置**：`agents/orchestrator/src/orchestrator/workflow/nodes.py:124`
**证据**：
```python
async def generate(state: MFState) -> dict[str, Any]:
    from mf_generators.rdkit_random.generator import RDKitRandomGenerator
    generator = RDKitRandomGenerator(seed=42)
```
**影响**：核心生成流程使用随机分子生成器而非 HFM-3D/FragFM 等真实模型，整个 AMGE 层形同虚设
**修复建议**：
1. 通过 generator-router-svc 路由到真实生成器
2. 或至少加载 HFM-3D 模型权重并使用其 generate 方法

### 1.5 [BLOCKER-005] uv.lock 锁文件缺失

**位置**：项目根目录
**证据**：`test -f uv.lock` 返回 MISSING
**影响**：无法确保依赖版本可复现；CI/CD 环境可能安装不同版本的依赖
**修复建议**：运行 `uv lock` 生成锁文件并提交到仓库

## 2. 一般问题（MAJOR 🟠）

> 偏离架构、未覆盖关键路径

### 2.1 [MAJOR-001] Critic 仅有 8 条规则，远低于架构承诺的 100+

**位置**：`agents/critic_agent/src/critic_agent/rules/checks.py`
**证据**：实际统计 @register_rule 装饰的函数共 8 个（R001-R008），架构 §4.2 Agent-7 声称"100+ 条质疑规则"
**分类统计**：
- 置信度相关：1 条（R001 low_confidence）
- 安全性/结构：1 条（R002 michael_acceptor）
- 多样性：1 条（R003 diversity）
- 合成路径：1 条（R005 synthesis_budget）
- 质量/异常：2 条（R006 quality_approval + R007 outlier）

### 2.2 [MAJOR-002] ADR（架构决策记录）完全缺失

**位置**：`docs/adr/`（空目录）
**证据**：无任何 `0001-0005-*.md` 文件
**影响**：关键架构决策（如选 Lorentz 而非 Poincaré、三层依赖纪律、双曲流形维度 128 等）没有书面记录
**修复建议**：创建以下 ADR：
- ADR-0001: 选择 Lorentz 模型而非 Poincaré 的理由
- ADR-0002: 三层依赖纪律
- ADR-0003: NATS 作为消息总线的选择
- ADR-0004: HUMU 编码维度 128 的依据
- ADR-0005: Orchestrator 与 Critic 分离 LLM 的防合谋设计

### 2.3 [MAJOR-003] 预留目录缺少文档

**位置**：`ui/`、`wetlab/`、`commercial/`
**证据**：三个目录均无 README.md 和 ARCHITECTURE.md
**影响**：接口承诺未记录、预留设计意图不清、后续开发者无法理解这些目录的目的
**修复建议**：每个预留目录创建 README.md（含"待实施"声明）和 ARCHITECTURE.md（详细设计规划）

### 2.4 [MAJOR-004] 数据摄入脚本不完整

**位置**：`data/ingestion/`
**证据**：
- ✅ 已实现：chembl_ingestion.py、crossdocked_ingestion.py、pdbbind_ingestion.py、reaction_ingestion.py
**修复建议**：按架构文档补齐各数据源的摄入脚本

### 2.5 [MAJOR-005] Agent 配置文件为空

**位置**：`configs/agents/`（空目录）
**证据**：无任何 YAML 配置文件
**影响**：无法验证架构 §4.2 要求的 Critic 与 Orchestrator 使用不同 LLM 模型族（防合谋设计）
**修复建议**：创建 `orchestrator.yaml`（Claude Sonnet 4.5）和 `critic.yaml`（DeepSeek-V3 或 Gemini）

### 2.6 [MAJOR-006] docker-compose 仅保留 DKI 版本

**位置**：`infra/docker/`
**证据**：仅存在 `docker-compose.dki.yaml`，缺少 `docker-compose.dev.yml`、`docker-compose.test.yml`、`docker-compose.minimal.yml`
**影响**：开发/测试/最小化部署场景无标准化的 compose 配置
**修复建议**：创建三个缺失的 compose 文件

### 2.7 [MAJOR-007] RuleRegistry 存在吞错模式（except: pass）

**位置**：`agents/critic_agent/src/critic_agent/rules/registry.py:43-45`
**证据**：
```python
except Exception:
    # Individual rule failures should not crash the critic
    pass
```
**影响**：规则执行失败时静默丢弃，无法诊断规则为何不工作（违反 Plan §1.2 模式 7）
**修复建议**：改为 `logger.exception("Rule %s failed", rule_id)` 至少记录日志

### 2.8 [MAJOR-008] ChEMBL 数据集不完整

**位置**：`zzzzz/Chembl/`（仅 4 个文件）
**证据**：ChEMBL 34 完整数据库应 > 2.4M 分子，当前仅 4 个文件
**影响**：HUMU 预训练缺少核心训练数据
**缺失数据集**：
- 🟠 PaRoutes 反应树数据
- 🟠 DUD-E 基准（HypSeek 评估）
- 🟠 CrossDocked 2020 v2（已存在文件名但需验证版本）
- 🟡 MOSES 2.0 / GuacaMol v3 基准
- 🟡 KRAS G12C Pilot 数据

### 2.9 [MAJOR-009] Orchestrator 的 humu_encode 节点为直通（pass-through）

**位置**：`agents/orchestrator/src/orchestrator/workflow/nodes.py:102-113`
**证据**：`humu_encode` 仅返回 `{"status": "encoded"}`，依赖 nl2obj 中的 CIG compiler 的 hash/随机编码，而非调用真实的 humu-encoder-svc gRPC 进行学习后的编码
**影响**：HUMU 双曲统一流形的核心价值（创新点 2）未在工作流中体现
**修复建议**：实现 gRPC 调用 humu-encoder-svc 的 EncodeMolecule/EncodePocket/EncodeRoute

### 2.10 [MAJOR-010] Orchestrator 的 refine 节点确认为 MVP stub

**位置**：`agents/orchestrator/src/orchestrator/workflow/nodes.py:429-455`
**证据**：函数文档明确标注 "MVP stub"
**影响**：CLM/RL 精炼循环（创新点 5 TAR + 知识蒸馏的关键环节）未实现
**修复建议**：实现 CLM 微调触发或保留生成器精炼

## 3. 补充建议（MINOR 🟡）

> 非阻塞，但能提升项目质量

### 3.1 [MINOR-001] entry-points 命名不一致

**位置**：`models/mf-generators/incremental_clm/pyproject.toml`
**证据**：注册名为 `iclm` 而非 `incremental_clm`
**影响**：`PluginRegistry.get_generator("incremental_clm")` 将失败，需使用 `iclm`
**修复建议**：统一命名，或同时注册两个名称

### 3.2 [MINOR-002] hfm_3d 的 3D→SMILES 解码未实现

**位置**：`models/mf-generators/hfm_3d/src/mf_generators/hfm_3d/generator.py:88-96`
**证据**：`_decoded_to_smiles()` 始终返回 None（因无条件调用 RDKit 构建失败后的 return None）
**影响**：HFM-3D 生成的 3D 坐标无法转换为 SMILES（需要训练后的解码器）
**修复建议**：训练 decoder 网络或在模型权重中包含解码器参数

### 3.3 [MINOR-003] data/samples 不足

**位置**：`data/samples/`
**证据**：仅存在 `molecules_100.csv` 和 `test_queries.json`，缺少 `pockets_10.json`、`reactions_50.txt`
**影响**：快速测试和 demo 缺乏代表性样本
**修复建议**：添加 pockets 和 reactions 的小样本

### 3.4 [MINOR-004] configs/agents 和 configs/services 目录为空

**位置**：`configs/agents/`、`configs/services/`
**影响**：无默认配置，每个 Agent/Service 可能使用硬编码参数
**修复建议**：添加 default.yaml 配置文件

### 3.5 [MINOR-005] 缺少 proto_gen 生成的 Python 代码

**位置**：`libs/mf-core/src/mf_core/proto_gen/`
**证据**：.gitignore 排除了 proto_gen/*.py（除 __init__.py），服务需要 fallback 到 JSON-over-gRPC
**影响**：开发体验受影响，需要额外的 `make proto-gen` 步骤
**说明**：这是设计选择（不提交生成代码），但文档应明确说明
