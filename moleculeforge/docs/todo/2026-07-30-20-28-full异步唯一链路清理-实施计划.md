# Full 异步唯一链路清理实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 full 异步 Orchestrator 设置为项目唯一默认执行骨架，迁移 UI 到规范 API，并删除并行兼容入口。

**Architecture:** 保留现有 `orchestrator-svc -> WorkflowGraph -> AgentRequestClient` 业务实现。先建立 API Gateway 的规范生命周期代理和 UI 调用，再删除旧 REST、同步、gRPC、Agent、Pipeline 和非 full 工作流分支，最后同步依赖、proto、部署和测试。

**Tech Stack:** Python 3.11、FastAPI、LangGraph、Redis Agent messaging、SQLite RunStore、原生 HTML/CSS/JavaScript、pytest、uv、protobuf、Docker Compose、Kubernetes、Helm。

## Global Constraints

- 唯一工作流必须是现有 full 实现，不重写领域链路。
- UI Bearer Token 只保存在页面内存。
- full 策略必须由用户提供真实值，不写入测试或生产伪默认值。
- 删除 state_only、engineering、同步 Python、gRPC、OrchestratorAgent、ReasoningPipeline、mvp_pipeline 和旧 REST 路由。
- 保留 full 链路、OIDC、run owner、证据恢复、项目、Pareto 和独立领域接口。
- 不修改 README.md。
- 不创建新的版本化并行实现。
- 每个提交使用中文 `<类型>: <描述>` 格式。
